変化し続ける環境でも崩れない AI エージェントの記憶を測る・育てる「EvoArena」と「EvoMem」

公開日：2026-06-11 arXiv：2606.13681 カテゴリ：cs.CL

この論文のひとことまとめ

ターミナルやソフトウェア、ユーザーの好みといった「使っているうちに変わっていく環境」でも、大規模言語モデル（LLM）を使った AI エージェントが頑健に振る舞えるかを測るベンチマーク群「EvoArena」を提案した論文です。あわせて、エージェントの記憶（メモリ）の更新履歴を、ソフトウェア開発で使う Git のパッチのように追記して残しておく仕組み「EvoMem」も提案しています。現行のエージェントは進化する環境では平均 39.6% の精度にとどまりますが、EvoMem を組み込むと精度が一貫して改善することを示しました。

なぜこの研究が重要か

AI エージェントは、コードを書く・ターミナルを操作する・ユーザーと長く対話するといった実用的な場面でどんどん使われ始めています。ところが、それらの能力を測る既存のベンチマークの多くは「ある時点で固定された環境」を前提にしています。

しかし現実の環境は止まっていません。API の仕様が変わり、ワークフローのルールが更新され、コードベースが成長し、ユーザーの好みも時間とともに移り変わります。「テストでは高得点なのに、実運用で環境が変わると急に弱くなる」というギャップが起きやすいのです。この論文は、その「変化への強さ」を正面から測り、改善しようとしている点で重要です。

背景：何が問題だったのか

既存のベンチマークは、いったん作られるとインターフェース・ルール・タスクの内容・成功条件が固定されがちです。近年はタスクを入れ替えたり、想定外のイベントを差し込んだりする「動的な評価」も登場していますが、この論文が注目するのは少し違う設定です。すなわち「同じ環境が、バージョンを跨いで持続的に変化し続ける（persistent environment evolution）」という状況であり、これはほとんど検証されてきませんでした。

ここで問題になるのが、エージェントの「記憶」の持ち方です。多くの記憶ベースのエージェントは、記憶を「単一の最新状態」として保持します。たとえば検索できる記憶バンクや、過去の出来事を貯めるストアです。この方式は、新しい情報が古い情報を安全に上書きしてよい場面ではうまく働きます。

問題は、環境のバージョンによって正しい振る舞いが違う場面です。論文はこれを「状態の崩壊（state collapse）」と呼んでいます。たとえばワークフローの権限ルールが新しく更新されたとき、その更新が、旧バージョンでは依然として有効な以前のルールごと上書きしてしまう、というケースです。すると、エージェントは「以前の振る舞い」と「それがどんな条件で有効だったか」という文脈の両方を一度に失ってしまいます。

そこで論文は「バージョン認識型の状態追跡（version-aware state tracking）」が必要だと主張します。これは、最新の記憶を保ちつつ、関連する過去の状態も呼び戻せて、しかも「各更新がなぜ起きたのか」まで推論できる能力を指します。

提案手法：何をしたのか

提案は大きく 2 つです。「測るための道具（EvoArena）」と「記憶を改善する仕組み（EvoMem）」です。

測る道具：EvoArena

EvoArena は、環境の変化を「漸進的に進化するリリース（progressively evolving releases）の連鎖（チェーン）」としてモデル化します。根底にある目標や設定は同じまま、インターフェース・ルール・ワークフロー・コードの状態・ユーザーの好みが時間とともに変わっていく、という捉え方です。代表的な 3 つの進化パターンを含みます。

Terminal-Bench-Evo

実行可能なワークフローの進化。ターミナル操作のベンチマーク Terminal-Bench をもとに、同じ目標を保ちながら、パッケージ・インストールの方針・入出力・権限・実装方法などをバージョンごとに変えます。

SWE-Chain-Evo

ソフトウェア／コードベースの進化。リポジトリの節目となるリリース（マイルストーン）を時系列の連鎖にしたもの。各ステップで、積み上がったリポジトリの状態とマイルストーンの指示を見てパッチを生成し、そのマイルストーンのテストで評価されます。

PersonaMem-Evo

社会的知能／好みの進化。長い対話の中で、同じユーザーの好みが時間とともに変化していく軌跡を扱います。各設問は、1 つの多肢選択問題と、さまざまな話題が混ざった長い会話履歴の組です。

EvoArena は「新しい変化への適応（forward adaptation）」と「いまも有効な過去の知識との両立（version compatibility）」の両方を評価する点が特徴です。論文の比較表（Table 1）では、EvoArena は「持続的な環境進化」「暗黙的な変化」「連鎖での評価」という 3 つの軸をすべて満たす唯一のベンチマークと位置づけられています。

記憶を育てる仕組み：EvoMem

EvoMem は、既存の記憶システムに「記憶がどう変化してきたかの明示的な記録」を追加する、軽量で Git に似た仕組みです。2 つの部品からなります。

  1. パッチ記録（Patch recording）

    記憶の更新のうち「非加算的（non-additive）な更新」、つまり既存の記憶を改訂・上書き・解釈し直すような更新だけを、追記専用（append-only）の履歴にパッチとして残します。単に情報が増えるだけの観測はベースの記憶にそのまま置けばよく、パッチは不要です。各パッチには、いつの更新か・更新前の内容・更新後の内容・更新理由・変更の要約・引き金になった証拠、が記録されます。

  2. パッチ拡張検索（Patch-augmented retrieval）

    問い合わせに対して、まず最新の記憶から手がかりを検索し、さらにパッチの履歴からも関連するパッチを取り出します。最終的に、両者を組み合わせた文脈をもとに意思決定します。これにより「最新の一貫した記憶」と「それがどう変化してきたかの軌跡」の両方を見て判断できます。

重要なのは、EvoMem が土台となる記憶の更新そのものは置き換えない点です。テキストの記憶バンク・ユーザープロファイル・記憶グラフ・スキルファイルなど、もとの更新の仕組みはそのまま使い、その前後の差分（Diff）を監視して記録します。そのため EvoMem は汎用的な仕組みであり、論文では 4 種類のエージェントに組み込まれています。

Terminus2

ターミナル操作のエージェント。

OpenHands

ソフトウェア開発のエージェント。

A-Mem

ノート型の記憶を持つエージェント。

Memento-Skill

再利用可能なスキルを記憶するエージェント。

結果：何が分かったのか

主な評価は EvoArena の 3 つのサブセットで行われ、加えて標準的なベンチマークである GAIA と LoCoMo でも評価しています。バックボーンには GPT-5.5、Gemini-3.1-Pro、Kimi-K2.6、Deepseek-V4-Pro など複数のモデルが使われました。

現行エージェントは進化する環境で苦戦する

ステップ精度の平均は、Terminal-Bench-Evo で 43.6%、SWE-Chain-Evo で 29.2%、PersonaMem-Evo で 46.5% でした（Abstract では 3 ドメイン平均で 39.6% と記載）。さらにチェーン精度になると下がります。論文は「個々のステップが解けても、持続的な進化を跨いだ信頼性にはつながらない」と述べています。

ドメイン ステップ精度（平均） チェーン精度
Terminal-Bench-Evo 43.6% 21.5%
SWE-Chain-Evo 29.2% 10.6%
PersonaMem-Evo 46.5% 39.1%

EvoMem を組み込むと精度が改善する

ステップ精度の平均改善は、Terminal-Bench-Evo で +2.4%、SWE-Chain-Evo で +0.5%、PersonaMem-Evo で +1.8% でした。標準ベンチでも GAIA で +6.1%、LoCoMo で +4.8% の改善が見られます。全設定の平均ではステップ単位で +2.6%、チェーン単位で +3.7% の改善です。

仕組みの分析：EvoMem が効く条件

仕組みの分析からは、EvoMem が効く条件も見えてきました。

Terminal-Bench-Evo

検索したパッチが実際に行動へ反映されたときに効果が大きく、パッチが取り込まれた場合の利得は +8.3% でした（取り込まれない場合は +2.6%）。

SWE-Chain-Evo

前後とも通過すべき回帰テスト（PASS_TO_PASS）の失敗率が平均 9.09% から 6.32% へ低下。「過去に確立した振る舞いを保ちつつ新しいマイルストーンに適応できる」ことを示しました。

PersonaMem-Evo

下流の推論に必要な好みの状態を保持する力（row-level capture）が 72.5% から 74.9% に上昇しました。

！

ただし改善は一様ではありません。一部のモデルや設定では性能が下がるケースもありました（たとえば SWE-Chain-Evo の Gemini-3.1-Pro や、PersonaMem-Evo の GLM-5.1）。

意義と限界

この研究の意義は、「変化する環境でのエージェントの記憶は、更新の履歴を検索可能な証拠として保持すべき」という設計の指針を、ベンチマークと具体的な仕組みの両面から示した点にあります。最新の状態を、それを生んだ過去の状態・理由・証拠と接続したまま保つことが、信頼性につながるという主張です。

一方で、論文は次のような限界も率直に認めています。

効果が一様でない

EvoMem の効果は一様ではなく、一部のモデル・設定では性能が低下します。

推論のボトルネックは残る

PersonaMem-Evo では、競合する好みの解決（conflict resolution）や単一パターンの転移（single-pattern transfer）でわずかに精度が低下。「パッチ履歴は証拠を使いやすくするが、最終的な推論が難しいケースではボトルネックが残る」と述べています。

条件付きの効果

EvoMem は、検索した変化の記録を実際に行動へ反映できたときにのみ効く、という条件付きの効果であることも分析で示されています。

まとめ

この論文は、タスク・コードベース・ワークフロー・ユーザーの好みが時間変化する環境でエージェントを評価する EvoArena を導入し、現行エージェントがそうした非定常な状況で限定的であることを明らかにしました。あわせて、記憶の更新履歴を Git のパッチのように残す EvoMem を提案し、進化する環境と標準ベンチの双方で精度と証拠の保持を改善できることを示しています。

用語集

LLM エージェント
大規模言語モデル（LLM）を頭脳として、ツール操作や対話などのタスクを自律的に進めるシステム。
持続的環境進化（persistent environment evolution, PE）
同じ環境やユーザーの状態が、バージョンを跨いで進化し続けること。EvoArena が中心に据える設定。
状態の崩壊（state collapse）
記憶を「単一の最新状態」として持つエージェントの失敗様式。旧バージョンで依然有効なルールまで上書きしてしまい、過去の振る舞いとその有効な文脈を失う。
バージョン認識型状態追跡（version-aware state tracking）
最新の記憶を保ちつつ、関連する過去の状態を呼び戻し、各更新の理由まで推論できる能力。
パッチ（patch）／追記専用履歴（append-only patch history）
記憶を改訂・上書きするような更新を、Git のパッチのように追記だけで記録した履歴。EvoMem の中核。
非加算的更新（non-additive update）
既存の記憶を改訂・上書き・解釈し直す更新。EvoMem はこれだけをパッチ化し、単に増えるだけの観測はパッチにしない。
ステップ精度／チェーン精度（Step Accuracy / Chain Accuracy）
個々のタスクを解けるかを測るステップ精度と、連鎖全体を最後まで誤りなく完遂できるかを測るチェーン精度。後者は持続的な信頼性を表す。
F2P / P2P テスト
SWE-Chain-Evo の評価で使うテスト。F2P（Fail-to-Pass）は修正前は失敗・修正後に通過するテスト、P2P（Pass-to-Pass）は前後とも通過すべき回帰テスト。
