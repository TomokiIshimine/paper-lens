片手で 2 つの作業を同時にこなすロボットハンド — 学習済みポリシーを「指の分担」で合成する DexCompose

公開日：2026-06-26 arXiv：2606.28323 カテゴリ：cs.RO / cs.AI / cs.CV / cs.LG

この論文のひとことまとめ

ロボットの多指ハンドに、別々に学習させた 2 つの操作スキルを「片手で同時に」実行させる枠組み DexCompose を提案した研究です。学習済みのスキル（ポリシー）を一切作り直さず凍結したまま、どの指がどちらの作業を担当するかを明示的に割り当てて合成します。例えば「棒を握ったまま、同じ手でドアハンドルを押す」といった作業を実現し、16 種類の合成タスクで平均 77.4% の成功率を達成しました。

+74.3pt 直接連結（Frozen grasp 3.09%）

なぜこの研究が重要か

人間は片手で器用に複数のことを同時にこなせます。ペンを握ったまま、その手の親指でスマートフォンを操作する、といった具合です。ロボットの多指ハンドにも同じことをさせたい場面は多くあります。

ところが、ロボットに「棒を握るスキル」と「ドアを押すスキル」を別々に学習させても、それを単純につなげて実行すると、後から動くスキルが手全体を操作してしまい、せっかく握っていた棒を落としてしまいます。スキルどうしが手の動きを奪い合うのです。

この研究は、すでに学習済みのスキルをそのまま再利用しつつ、片手で複数作業を両立させる方法を示しました。スキルを作り直さなくてよいため、再利用しやすく、組み合わせ数が増えてもスケールしやすい方向性を提示している点に意義があります。

背景：何が問題だったのか

器用な操作（dexterous manipulation）、つまり多指ハンドによる細かい操作では、片手であるスキルの結果を保ったまま別のスキルを実行する必要がある場面が多くあります。論文が挙げる例は「棒を握った後、同じ手でドアハンドルを押す」です。

しかし、2 つの単一タスク用ポリシー（policy、ロボットが状況に応じて行動を決める方策）を単純に連結（chaining）すると不安定になります。後続のポリシーが手全体を制御してしまい、握りを維持するための指の動きを上書きしてしまうからです。論文はこれを、同じ行動空間（action space、ロボットが取りうる動作の集合）を共有する 2 つの目的、すなわち「既存の握りの保持」と「新しい操作の実行」のあいだに起こる破壊的干渉（destructive interference）と呼んでいます。

！

専用ポリシーを学習し直す方法はスケールしない。合成タスクごとに専用ポリシーを学習し直せばよいように思えますが、論文はこれをスケールしない方法だと指摘します。n 個の握り保持スキルと m 個の下流操作があると、その組み合わせとして n×m 個のポリシーが必要になってしまうからです。

既存の指割り当て（finger allocation）の研究も、握りの生成・データ構築・ポリシー学習の段階で、あらかじめ決めた指の割り当てやタスク構成に依存しており、異なる組み合わせへ広げにくいという課題がありました。一方で近年は、大規模な器用な握りのデータセットが整い、再利用できる手全体（full-hand）の握りコントローラが入手しやすくなっています。そこで論文は「学習済みの器用操作ポリシーを、タスク間で余っている手の自由度を見つけて活用しながら合成できないか」という問いを立てます。

提案手法：何をしたのか

中核となる着想（key insight）は、「学習済みポリシーの中で実質的に使われていない自由度（idle DoFs、遊んでいる自由度）は、別の動作を付け足すための再利用可能な資源だ」というものです。論文はタスクの組み合わせを、身体（embodiment）レベルでの資源割り当て問題としてとらえ直します。

この問題を 2 つに分解します。1 つは discovery（各ポリシーが実際に必要としている動作の次元を特定すること）、もう 1 つは composition（各ポリシーを割り当てられた自由度だけで動かし、2 つの目的を同時に達成すること）です。DexCompose はこれらを次の 2 段階で実現します。

段階 1：指の帰属付け（Finger Attribution、学習不要）

まず、どの指がどちらの作業を担当するかを決めます。この段階は追加の学習を必要としません（training-free）。

  • まず Task A（例: 棒を握る）を成功させた後の状態を集めます。そして「解放テスト（release test）」を行います。これは一部の指をあえて解放してみて、それでもオブジェクトが安定して保持され続けるかを観察する手続きで、握りに本当に必要な指を見つけ出します。
  • 5 本の指それぞれについて、Task A のために保持する指（マスク値 1）か、Task B のために解放する指（マスク値 0）かを表す二値の所有権マスク（ownership mask）を定義します。この指単位のマスクは、関節単位のマスクへと展開されます。
  • 各マスクの候補は 2 つの指標で評価されます。保持率（retention rate）は、解放テスト中に Task A が成功し続けるかを測ります。クリーン解放率（clean-release rate）は、解放した指が接触の支えを残さずきれいに離れるかを測ります。
  • 最終的なマスクは、保持の安定性・クリーンな解放・残った器用さのバランスを取って選ばれます。この選択は「タスクを考慮した割り当てエージェント（task-aware allocation agent）」が担い、論文ではこれを大規模言語モデル（large language model、LLM）で実装しています。
！

「あえて成功率の高い握りを選ばない」判断。ボールを握るとき、親指と人差し指で持つと保持の成功率は約 7% 高くなりますが、人差し指がふさがるため後続のボタン押しやドア開けが制限されます。LLM は保持率がやや低い「親指・薬指・小指」での握りをあえて選び、人差し指を次の作業のために空けておく、という判断をします。

段階 2：二重残差スタビライザ（Dual Residual Stabilizer）

次に、決めた分担にもとづいて 2 つのポリシーを実際に動かします。マスクが行動の所有権を定めます。すなわち、Task A は保持する指の関節だけを制御でき、Task B は手首と解放された指の関節を制御します。

ここで、合成によって生じる外乱を補うため、2 つの残差（residual、既存の出力に加える補正）モジュールを学習します。これが「二重」スタビライザの名前の由来です。

Task A 側有界残差スタビライザ

下流の動きや指の解放による揺さぶりを補償するため、保持する指の関節に対して有界な（一定の範囲に収まる）補正を加えます。

Task B 側文脈認識残差

凍結した下流ポリシーが出す本来の行動に対し、Task B が所有する行動の範囲内だけで有界な補正を加えます。

結合合成行動の生成

最終的な合成行動は、固定した所有権マスクで Task A 側と Task B 側を組み合わせて作られます。

これらの残差モジュールはゼロに近い値で初期化されます。そのため、残差を学習する前の状態は、保持する指には Task A の参照動作を、手首と解放した指には凍結した Task B ポリシーをそのまま実行する状態から始まります。学習の際は、マスク・2 つの元ポリシーは固定したまま、2 つの残差モジュールだけを最適化します。

この手法の重要な特徴は、元の 2 つの学習済みポリシーを一切改変せず、推論時（実行時）に合成する点です。タスクのペアごとにポリシーを学習し直す必要がありません。

結果：何が分かったのか

実験はシミュレータ Isaac Lab 上で、多指ロボットハンド Shadow Hand を使って行われました。

タスクは、Task A に 4 つのオブジェクト保持スキル（ボールを握る、マグを注ぐ、缶を持つ、棒を持つ）、Task B に 4 つの操作スキル（ドアを開ける、ボタンを押す、電子レンジを開ける、スイッチを入れる）を割り当て、その組み合わせとして 4×4＝16 の合成タスクを構成しています。評価指標は合成成功率（Composition Success Rate）で、Task A のオブジェクトが実行を通じて保持され、かつ Task B も成功した場合のみ成功とみなします。

主要な結果は次のとおりです（数値は原論文の Table 1 などにもとづきます）。

手法 合成成功率（平均, 高いほど良い） DexCompose との差
DexCompose（完全版） 77.43±2.64% —
残差学習（最強ベースライン） 61.60±2.31% −15.8 ポイント
直接連結（Frozen grasp） 3.09±0.72% −74.3 ポイント

直接連結ではほぼ完全に失敗しており、独立に学習した 2 つのポリシーをそのままつなぐと深刻な干渉が起きることを示しています。特に大きな改善は、電子レンジを開ける・スイッチを入れる、といった難しいタスクで見られました。

論文は、合成しても元のポリシーの性能を大きく損なわないかも分析しています。直接連結方式では Task A 側の保持率が 0.102 と非常に低く、最初に握ったものを頻繁に失っていました。これに対し DexCompose は Task A 側 0.811・Task B 側 0.893 という高い保持率を達成しています。

0.811 DexCompose の Task A 保持率
（握ったものを保ち続ける）
0.893 DexCompose の Task B 保持率
（下流操作の達成度）
0.102 直接連結の Task A 保持率
（握ったものを頻繁に失う）

失敗の内訳を見ると、スキルが切り替わる遷移段階での失敗が支配的でした。これは遷移が最も難しく、スタビライザが握りの安定性を保つうえで重要であることを示しています。

アブレーションとマスク選択エージェントの比較

各構成要素を取り除くアブレーション（ablation、機能を 1 つずつ外して効果を測る実験）では、Task A 側の残差を外すと平均成功率が 9.13% まで大きく落ち込みました。これが「第一のタスクの結果を保持する」中心的な仕組みであることが確認されています。また、行動マスクを外して全次元に補正を書き込む方式（従来の残差学習に相当）よりも、マスクで所有権を構造的に強制するほうが大幅に優れていました。

マスクを選ぶエージェントについても比較しています。LLM による選択（平均 73.0%）は、保持率を優先するヒューリスティック（平均 66.5%）を上回りました。なお LLM には OpenAI の GPT-5.4 を温度パラメータ 0（決定的な選択）で用いています。

マスク選択エージェント 平均成功率（高いほど良い）
LLM（GPT-5.4, 温度 0） 73.0%

意義と限界

この研究の意義は、身体に内在する冗長性（余った自由度）を再利用可能な資源としてとらえ、学習済みの器用操作ポリシーを、タスクごとの作り直しなしに柔軟に合成できる方向性を示した点にあります。論文は、構造化された行動の所有権がタスク間の干渉を減らし、合成操作の成功に重要であることを実証しました。

一方で限界も明示されています。

限界 1合成は 2 スキルまで

現在の枠組みは、一度に 2 つの逐次的なスキルを合成することに焦点を当てています。複数のスキルが相互に作用する、より長い時間にわたる合成への拡張が、今後の重要な課題として挙げられています。

限界 2シミュレーション環境

本研究の実験はシミュレーション環境（Isaac Lab）で行われている点にも留意が必要です。

まとめ

DexCompose は、学習済みの 2 つのハンド操作ポリシーを凍結したまま、指ごとに役割を割り当てて合成し、片手で 2 つの作業を同時に実現する枠組みです。指の帰属付けで担当を決め、二重残差スタビライザで干渉を抑えることで、16 タスク平均 77.4% の合成成功率を達成し、直接連結や残差学習を上回りました。

用語集

器用な操作（dexterous manipulation）
多指ハンドによる細かい操作。本論文では片手で複数タスクを両立させることが課題。
ポリシー（policy）／ポリシー合成（policy composition）
ポリシーは状況に応じて行動を決める方策。合成は学習済みの複数ポリシーを組み合わせて複合タスクを実行すること。本論文では実行時に元ポリシーを改変せず合成する。
破壊的干渉（destructive interference）
既存の握り保持と新タスク実行が同じ行動空間を奪い合い、互いを壊してしまう現象。
指の帰属付け（finger attribution）／行動の所有権（action ownership）
どの指（または関節）をどちらのタスクが制御するかを明示的に割り当てること。
解放テスト（release test）
一部の指を解放してオブジェクトが安定保持され続けるか観察し、保持に必須の指を特定する手続き。
所有権マスク（ownership mask）
指または関節ごとに Task A 保持か Task B 解放かを示す二値マスク。
二重残差スタビライザ（dual residual stabilizer）
Task A 保持用の有界残差と、Task B 用の文脈認識残差という 2 つの補正モジュール。
残差（residual）
既存コントローラの出力に加える学習済みの加法的な補正。
遊んでいる自由度（idle DoFs）
学習済みポリシー内で実質使われていない動作の次元。合成のための再利用資源とみなす。
Shadow Hand
実験で用いた多指ロボットハンド。
