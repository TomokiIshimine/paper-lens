「誰が誰を押すか」を図で描いて動画を作る — インタラクショングラフで多物体の動きを操る GraphVid

公開日：2026-07-23 arXiv：2607.21580 カテゴリ：cs.CV / cs.AI

この論文のひとことまとめ

1 枚の静止画から動画を作るとき、「どの物体がどう動くか」をユーザーが指定する方法が課題でした。本論文が提案する GraphVid は、画像に写る物体を点（ノード）、物体同士の関わり方を矢印（有向エッジ）として表した「インタラクショングラフ」を編集することで、動きを対話的に指定できる枠組みです。学習済みの動画生成モデル本体は凍結（重みを更新せず、そのまま使うこと）したまま、グラフを条件情報に変換する小さな部品だけを学習させます。その結果、学習可能パラメータ 0.6B・学習データ 27K クリップという小規模さで、桁違いに大きい既存手法に匹敵する制御性と映像品質を達成しました。

なぜこの研究が重要か

1 枚の写真を動画にする技術（Image-to-Video 生成、以下 I2V）は急速に実用に近づいていますが、「思った通りに動かす」のは依然として難しい部分です。静止画には未来の情報が一切含まれないため、モデルはどんな動きが妥当かを推測するしかなく、本質的に曖昧な問題になります。

そこで従来は、ユーザーが動きの軌跡を描いて渡す方式が主流でした。しかしこの方式は、物体が増えるほど負担が急激に大きくなります。3 つの物体が絡み合うシーンなら、3 本の正確な軌跡を破綻なく描き分けなければなりません。

GraphVid が提案するのは、この入力を「押す」「引く」「持ち上げる」といった関係のラベルに置き換えるという発想です。人間が動きを説明するときに使う語彙そのものをインターフェースにすることで、専門的な作図技能なしに多物体の動きを指定できるようになります。

背景：何が問題だったのか

論文は既存の制御可能 I2V 手法を整理したうえで、3 つの限界を挙げています。

限界 1物理を低レベルの信号として符号化する

力や速度場、構造化された物理アノテーションを制御信号として与える、物理を意識した（physics-aware）手法があります。しかし物理を低レベルの制御場や、あらかじめ決めたカテゴリとして表現するため、オープンドメイン（対象を限定しない、あらゆる場面）における複数の実体同士の複雑な相互作用を表現しきれません。

限界 2低レベルの幾何的手がかりに条件付ける

点の軌跡やオプティカルフロー（フレーム間で画素がどこへ動いたかを表す流れ場）、セグメンテーションマスク、疎なバウンディングボックスなどを与える方式です。多物体シーンでは制御が煩雑になり、少数の制御に生じた小さな誤りが、全体としては非現実的な動き（接触の不整合、滑り、物体の貫通、非同期な挙動）を引き起こします。オクルージョン（物体が別の物体に隠れること）や重なりの下では、そもそも軌跡の指定自体が曖昧になります。

限界 3データ取得コストの高さ

軌跡ベースの手法も、物理を条件として与える（physics-conditioned。限界 1 で述べた physics-aware な手法と同じ系統です）手法も、密なモーションアノテーション・軌跡・オプティカルフロー・物理ラベルを含む大規模なキュレーション済みデータセットに強く依存します。論文が挙げる具体例では、Wan-Move は 2M（200 万）サンプル、Motion Prompting は 2.2M、Motion-I2V は 10M サンプルで学習しています。この規模のデータを揃えるのは容易ではなく、多様な環境へスケールさせにくいという問題があります。

提案手法：何をしたのか

全体の流れ

GraphVid の処理は 5 段階です。

  1. 物体を検出してノード埋め込みへ

    入力画像 I₀ から物体を検出し、ノード埋め込み（ベクトル表現）に符号化します。

  2. MLLM が関係エッジを抽出

    MLLM（マルチモーダル大規模言語モデル。画像とテキストの両方を扱える LLM）が関係エッジを抽出し、初期インタラクショングラフを構築します。

  3. ユーザーがグラフを編集

    ユーザーが画像上で直接操作して望むダイナミクスを指定し、グラフを編集します。

  4. Edge-Aware Graph Reasoning で条件付けトークンへ

    編集されたグラフを Edge-Aware Graph Reasoning（エッジを考慮したグラフ推論）で処理し、conditioning tokens（条件付けトークン）に変換します。

  5. 凍結した動画生成 transformer を誘導

    凍結された動画生成 transformer をそのトークンで誘導し、相互作用と整合した動画を生成します。

インタラクショングラフとは何か

グラフ G = (V, E) は属性付きの有向グラフです。各ノード v_i は入力画像中で検出された entity（実体、物体）に対応します。各有向エッジ e_ij は物体 i から物体 j への関係タイプ r_ij（例: push, pull, lift, hold）を符号化し、実体同士がどう影響し合うかを記述します。加えて任意で、粗い方向と大きさといった定性的な物理的手がかりも持てます。

「ある物体だけを回す」のような、相手のいない単項の指示は自己ループエッジ e_ii として表現します（例: rotate, move, scale）。目標は条件付き動画生成器 p(I_{1:T} | I₀, G) を学習することです。

ノードの中身は 3 つの情報の連結です。バウンディングボックス内の画像領域から得た視覚埋め込み、物体ラベルのテキスト埋め込み、そして正規化されたバウンディングボックス座標。これにより外観・意味的な同一性・空間的な位置を同時に捉えます。エッジのほうは、始点（source）の物体と終点（target）の物体の間で意図された相互作用を表す、自由な語彙のテキスト記述であり、テキスト埋め込みモデルで符号化されます。あらかじめ決めた関係カテゴリに縛られない点がポイントです。

Edge-Aware Graph Reasoning：エッジの意味を捨てない

グラフニューラルネットワークの標準的な手法である GCN は、エッジを「つながっているか否か」という二値の接続性信号としてしか扱わず、主にノードの特徴を伝播させます。しかし物理的な相互作用をモデル化する場合、関係のタイプそのものが運動の仕方を直接決めます。「押す」と「引く」では結果が正反対です。関係の属性を無視すると、グラフは単なる空間的な隣接情報に退化してしまいます。

そこで本手法は GINEConv（edge-aware Graph Isomorphism Network、エッジ特徴を扱えるグラフ同型ネットワーク）を採用します。ノード同士が情報をやり取りする message passing の集約ステップにエッジの意味を直接注入する仕組みです。ノード特徴とエッジ特徴を学習可能な MLP（多層パーセプトロン。単純な全結合ニューラルネットワーク）で共有の隠れ空間に射影し、L 層の GINEConv を適用します。

h^(l+1)_i = MLP^(l) ( h^(l)_i + Σ_{j∈N(i)} ReLU( h^(l)_j + a_ji ) )

記号の意味は次のとおりです。h は各ノード（物体）の表現、N(i) はノード i と繋がっている相手のノード、a_ji はエッジ j→i の特徴、ReLU は負の値を 0 に潰す標準的な活性化関数です。式は「自分の表現に、繋がっている相手の表現とその関係の特徴を足し合わせたものを混ぜ、MLP を通して次の層の表現を作る」と読めます。

この定式化により、各ノードの表現は「近くにどんな物体があるか」だけでなく「それらとどんな物理的関係にあるか」にも条件付けられます。

Graph-to-Video Adapter：本体には触らない

事前学習済みの DiT（Diffusion Transformer）バックボーンである LTX-Video は凍結したまま使います。そのうえで、グラフ埋め込みを transformer の入力空間と互換な conditioning tokens に変換する軽量なアダプタを導入します。

相互作用を織り込んだノード埋め込み h_i を MLP で transformer の潜在空間（モデルが内部で扱う圧縮された表現の空間）へ射影し、各ベクトルを意味的な条件付けトークンとして扱います。シーンごとに物体数が変わるため、ノード系列は最大長 N_max まで空のトークンで埋められます（パディング）。得られたトークンをエッジのテキストトークンと連結し、エンコーダ側の隠れ状態（encoder hidden states。条件情報として transformer に渡される入力）として渡します。こうすることで transformer の self-attention（自己注意機構。系列内の要素同士の関連度を計算する仕組み）が実体間の相互作用を推論し、グラフ構造を生成時の動きへ翻訳できるようになります。

学習

凍結した DiT を新しい「グラフ条件付け」という入力の種類に適応させるため、各 transformer ブロックの Q・K・V（self-attention の Query・Key・Value。注意の計算に使う 3 つの射影）と出力射影層に LoRA（Low-Rank Adaptation。事前学習済みの重みを変えずに少数の追加パラメータだけで適応させる手法）を注入します。

学習目標は、事前学習済み拡散モデルが用いる flow-matching（フローマッチング）です。まず目標動画 x₀ を潜在空間に符号化します。次に 0 と 1 の間の混合比 t を確率的に選び（論文は logit-normal 分布を使います。0 や 1 の近くより中間の値が出やすい分布です）、ノイズ x₁ と混ぜて x_t = (1−t)x₀ + t x₁ を作ります。損失は L_CFM(θ) = E[ ‖ v_θ(x_t, t, c) − (x₁ − x₀) ‖²₂ ] です。

平たく言えば、x₁ はノイズ、x_t は目標動画とノイズを比率 t で混ぜた中間状態です。モデル v_θ はその中間状態と混合比 t、そして条件 c（ここではグラフ由来の条件付けトークン）を受け取り、動画とノイズを結ぶ「進む向き」（x₁ − x₀）を予測するよう学習します。生成時はこの向きを逆にたどることで、ノイズを動画へと運びます。

i

学習時に更新されるのは GNN のパラメータ、Graph-to-Adapter の MLP 層、LoRA モジュールだけです。VAE（動画を圧縮された潜在表現に変換し、また元に戻す部品）と DiT バックボーンは凍結のままです。

GraphVid-Bench：グラフ付き動画データセット

既存の動画生成ベンチマークは主にテキストプロンプトや低レベルのモーション手がかりに依存しており、物体レベルの相互作用を制御する評価が限られていました。そこで著者らは、動画とインタラクショングラフを対にした GraphVid-Bench を構築しています。

規模は約 27K の相互作用中心（interaction-centric）な動画クリップで、全クリップを 81 フレーム / 16 fps に標準化しています。1 グラフあたりのノード数は平均 7.76（中央値 5.0）、エッジ数は平均 4.85（中央値 4.0）。相互作用の複雑さで分類すると、次のような内訳です。

相互作用の複雑さ クリップ数 位置づけ
相互作用なし（N=0） 3,881 件 自然な物体運動のみ
単一相互作用（N=1） 10,982 件 1 組の相互作用
複数相互作用（N>1） 12,641 件 複数が同時に絡む

N=0 のサンプルは実体間の直接的な相互作用がない自然な物体運動を含み、一般的な動画ダイナミクスを学ぶベースラインになります。推論時にユーザーがエッジを追加できる設計なので、こうしたサンプルは「新しい相互作用が導入されたときにシーンがどう変わるか」を学ぶのに役立ちます。

学習データは 3 つのオープンソースデータセット（WISA-80K、Something-Something v2、MagicData）から構成され、評価用には DAVIS 2017 と MoveBench から抽出・厳選した、評価専用の分割（テスト split）を用意しています。前処理では Qwen3-VL で各動画の支配的な運動源を分類し、個別の物体同士の相互作用（discrete object interactions）と判定された動画のみを残します。カメラの動きが支配的な動画などを除くためです。リサイズは 512×288 で、中央だけを切り出す center-crop ではなく dynamic letterboxing（元のアスペクト比を保ったまま余白を足してリサイズする手法）を使い、フレーム端の重要な相互作用が切り落とされるのを防いでいます。

結果：何が分かったのか

主結果

主評価は MoveBench の、相互作用が中心となるサブセットです。指標は FID・FVD（低いほど良い、画質と分布整合性）、PSNR・SSIM（高いほど良い、再構成の忠実度）、そして EPE（End-Point Error。予測と正解のオプティカルフローの平均変位で、生成された動きが意図した相互作用に従っているかを直接測る。低いほど良い）です。

同程度以下のデータ規模で学習した手法との比較では、GraphVid が広く優位に立ちます。WISA 比では FID を 34.5% 削減（25.98→17.02）、FVD を 7.8% 削減（107.89→99.42）、PSNR を 5.9% 向上（15.08→15.98）、SSIM を 15.0% 向上（0.53→0.61）、EPE を 29.3% 改善（4.1→2.9）。Motion-I2V 比では FID −39.9%、FVD −37.6%、PSNR +61.9%、SSIM +60.5%。FlashMotion 比では FID を 10.5% 削減し、MagicMotion 比では約 36% 削減しています。

動きの正確さを測る EPE では、GraphVid の 2.9 は比較可能な軌跡ベース手法すべて（Motion-I2V 3.9、FlashMotion 3.8、Tora 3.3、MagicMotion 3.2）を下回りました。明示的なモーション教師信号を一切使わずに、モーション誤差を 9.4〜25.6% 削減したことになります。

一方で Wan-Move は絶対値の指標では最良です。ただし約 2M 動画で学習し、14.5B パラメータのバックボーンを使っています。論文は、GraphVid が約 2 桁少ない学習データと約 24 分の 1 のモデルパラメータで競合する性能を達成した、という位置づけで述べています。

推論速度

GraphVid は比較手法中で最速の 200 秒でした。Wan-Move の 1800 秒、Tora の 1200 秒、WISA の 1000 秒と比べて大幅に高速です。論文はこれを、軽量なインタラクショングラフ条件付けと LoRA ベースの統合により、重い補助モーションエンコーダや大規模なモーション予測モジュールが不要になったためだと説明しています。

アブレーション：どの要素が効いているか

エッジの意味は必要か。何を条件として与えるかを比べると、次のようになります。

条件として与えるもの FID↓ FVD↓ PSNR↑
LTX のテキストプロンプト＋初期画像のみ 20.04 — —
グラフの構造（トポロジー）のみ 17.52 — 16.88
エッジ意味を含むフル構成 17.02 99.42 15.98

ここでトポロジーとは、どのノードがどのノードと繋がっているかという配線図のことです。グラフの構造だけを与えても FID は 20.04 から 17.52 へ改善し、空間的な境界を明示することが動きの局在化に効くと分かります。ただし、エッジのテキスト的な意味がないと「pushing」と「pulling」のような相反する相互作用を区別できず、深刻な動きの曖昧さが生じます。エッジ意味を含むフル構成が最良で FID 17.02、FVD 99.42 でした。なお PSNR に限っては、エッジテキストなしの 16.88 のほうがフル構成の 15.98 より高い値が報告されています。

アブレーションノード数の上限

最大ノード容量は 30 が最良（FVD 99.42）で、128 や 256 を一貫して上回りました。実世界のシーングラフは、ノード数に対して繋がりが少ない疎な構造です。そのため必要以上に長い枠へ空のトークンを詰めると、self-attention が本来注目すべき情報に集中できず品質が落ちる、というのが著者らの説明です。全実験で上限 30 を採用しています。

アブレーションLoRA の rank

rank を上げると全指標が一貫して改善しました。16→128 で FID −7.2%、FVD −3.6%、PSNR +16.6%、SSIM +5.2%。報告実験ではすべて rank 128 を使用しています。

アブレーションバックボーンへの依存

2B の LTX を 5B の Wan 2.2 に置き換えても、FID 17.29 / FVD 100.01 と競合する性能を保ちました。エッジを考慮した GNN とアダプタが、グラフを別の潜在空間へ対応付けられているということです。グラフ表現が、土台となるモデルに依存しない（backbone-agnostic）条件付け信号であることを示しています。

アブレーションエッジそのものの寄与

意味的なエッジ接続と message passing の層を省き、ノード情報だけを使う変種でも学習は収束し、ベースライン水準の制御は得られます（FVD 103）。しかし相互作用する実体間の複雑な物理的依存を十分には解けず、明示的なエッジ特徴を統合すると FVD 99.42、PSNR 15.98 へ全指標が改善しました。

学習コストの推定は、NVIDIA A100 の最大 TDP（Thermal Design Power、熱設計電力。消費電力の上限の目安）を 400W と仮定したものです。

定性的な違い

論文の図では、ベースラインとの差が具体的に示されています。

2 隻の船

ベースライン：2 隻の運動軌跡を分離できないか、生成中に視覚アーティファクトを持ち込む。

GraphVid：ユーザー指定の相互作用と整合した発散する軌跡を生成。

ジョギング

ベースライン：被写体をフレーム外に消したり、ジョギングではなく歩行を生成したり、モーションブラー（動きによる被写体のぶれ）を出したりする。

GraphVid：被写体の同一性を安定に保つ。

握手

ベースライン：動きを突然終了させたり手をぼやけさせたりする。

GraphVid：接触が一貫した滑らかな系列を生成。

意義と限界

著者らは、単一画像から構築した有向インタラクションシーングラフを通じて多物体ダイナミクスの対話的制御を可能にした最初のフレームワークである、と自らの知る限りという留保付きで述べています。

技術的な要点は 2 つあります。

  • 運動を「低レベルの信号」ではなく「実体間の構造化された相互作用」としてモデル化したこと。
  • 凍結した動画 DiT に、パラメータ効率的な LoRA 条件付けで接続したこと。本体の重みを触らないため、事前学習で身についた「自然な動きらしさ」の感覚（生成の事前分布）を壊さずに、構造化された制御だけを足せます。
!

共通する失敗モードは、シーングラフを構築する段階での物体検出の粒度です。VLM（Vision Language Model。画像と言語を扱うモデルで、ここでは前述の MLLM と同じくグラフの自動構築を担う部品を指します）が、小さい要素や記号的な要素を独立したノードとして分離できない場合に起こります。

例として、眠っているクマの上に描かれた小さな「Zzz」記号に回転を適用しようとしたケースが挙げられています。VLM はこの目立たないテキストを独立ノードとして切り出せませんでした。その結果、相互作用のベクトルが最も近い高信頼度の物体、つまりクマ本体に誤って結び付けられます。意図した記号ではなく被写体全体が丸ごと回転してしまい、フレーム間で深刻な幾何学的歪みが生じました。

著者らは、細かい粒度の相互作用制御に対して、現行のゼロショット検出（事前に学習していない対象も、その場で名前を頼りに検出しようとする方式）のパイプラインには限界があるとしています。そのうえで、将来のシステムは明示的なノード指定や対話的セグメンテーション（ユーザーが対象領域をその場で指定する方式）から恩恵を受けうると述べています。

このほか、ノード容量を過大にすると、空きを埋めるパディングが self-attention にノイズを持ち込み、関係の手がかりを薄めてしまうこと、トポロジーのみのグラフでは「押す」と「引く」を区別できないことも、アブレーションから確認された制約です。

広い影響についても言及があります。複雑なモーションアノテーションではなく直感的なインタラクショングラフでシーンダイナミクスを指定できるため、クリエイティブメディア制作、バーチャルプロトタイピング、物理現象の教育的可視化、ロボティクスや embodied AI（身体を持つ AI）研究のシミュレーション環境などへの寄与が期待されます。一方で、最小限の入力からリアルな動画を作れることは、誤情報やなりすましを含む改変メディアの作成にも寄与しうる懸念があります。著者らは、透かし（watermarking）、来歴追跡（provenance tracking）、検出手法といったセーフガードの探究を今後の研究に促しています。

まとめ

GraphVid は、動画生成の制御インターフェースを「軌跡を描く」から「関係を編集する」へ置き換えた研究です。物体をノード、相互作用を有向エッジとするグラフを条件として与え、エッジの意味まで扱える GNN と軽量アダプタで凍結した動画 DiT に接続することで、0.6B の学習可能パラメータと 27K クリップという小規模な構成で、桁違いに大きい既存手法に匹敵する制御性・品質・最速の推論速度を実現しました。残る課題は、グラフを自動構築する段階での物体検出の粒度であり、明示的なノード指定や対話的セグメンテーションが次の一手として示されています。

用語集

インタラクションシーングラフ
ノードが入力画像中で検出された実体、有向エッジが物体 i から j への関係タイプ（push, pull, lift, hold 等）と任意の定性的物理手がかり（粗い方向・大きさ）を符号化するグラフ。相手を伴わない単項の指示（rotate, move, scale 等）は自己ループエッジで表す。
Edge-Aware Graph Reasoning
有向エッジの属性に message passing を条件付けるモジュール。GINEConv を用いてエッジの意味を集約ステップへ直接注入する。
GINEConv
エッジ属性を集約に注入できる GNN 層。標準の GCN がエッジを二値の接続性としてしか扱わない点を克服する。
conditioning tokens（条件付けトークン）
グラフ埋め込みを DiT の潜在空間へ射影して得る意味的トークン。エッジのテキストトークンと連結し、エンコーダ側の隠れ状態（encoder hidden states）として渡される。
DiT (Diffusion Transformer)
transformer ベースの拡散モデル。大規模化により長距離の時間的一貫性と視覚忠実度が向上する、動画合成の主流アーキテクチャ。本手法は事前学習済みバックボーン LTX-Video（Appendix B では LTX 2B と記載）を凍結して用いる。
LoRA (Low-Rank Adaptation)
事前学習済みの重みを変更せず、少数の学習可能パラメータで適応させる手法。本手法では attention の to_q, to_k, to_v, to_out.0 に注入。
flow matching 目的関数
本手法の学習損失 L_CFM。x_t = (1−t)x₀ + t x₁ に対して v_θ(x_t, t, c) が (x₁ − x₀) を予測するよう学習する。
