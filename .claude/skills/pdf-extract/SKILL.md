# pdf-extract — 論文 PDF のテキスト化・要点抽出

選定済みの論文 1 本について、PDF を取得・テキスト化し、日本語解説記事の素材となる要点を `analysis.md` に構造化して残す手法を定義する。

## このスキルが規定すること

1. PDF の取得とテキスト化（`scripts/extract_pdf.py`）
2. 抽出した本文テキストから要点を `analysis.md` にまとめる際のフォーマットと忠実性のルール

## 実行環境

- ランタイム: Python 3.9+
- 実行は `uv run`。依存ライブラリ（`pypdf`）はスクリプト先頭の PEP 723 ブロックで自己宣言しており、`uv` が**スクリプト専用の隔離環境で自動解決**する。メイン環境を汚さず、手動の `pip install` は不要（初回のみ依存取得のため数秒のセットアップが入る）。

## PDF の取得とテキスト化

`scripts/extract_pdf.py` に選定結果 `selected.json`（`pdf_url` / `arxiv_id` を含む）と出力先テキストパスを渡すと、PDF をダウンロードし全文テキストを書き出す。

```bash
uv run .claude/skills/pdf-extract/scripts/extract_pdf.py \
  --selected "work/<run-id>/selected.json" \
  --out "work/<run-id>/paper_fulltext.txt"
```

- 出力 `paper_fulltext.txt` はページ区切り（`--- page N ---`）付きの素のテキスト。解説記事の素材は次節の `analysis.md` にまとめる。

### 一次資料と二重照合の約束（単一の真実源）

本スキルが生成する 2 ファイルの位置づけと、fact-check がそれをどう使うかをここで一度だけ定義する（他節・他ファイルからはこの定義を参照する）。

- `paper_fulltext.txt` = **原論文一次資料**。`work/<run-id>/` に保全し、揮発・上書き・加工しない。
- `analysis.md` = 次節の規約に従う**抽出要約**。
- fact-check は `analysis.md`（抽出要約）と `paper_fulltext.txt`（原文）を**二重の照合元**とし、両者が食い違う場合（＝解析段で紛れ込んだ誤り）も検出対象とする。検出対象の判定基準（重大度など）は article-reviewer 側の責務であり、本スキルでは規定しない。
- PDF が取得できない・テキスト化できない場合はスクリプトが非ゼロ終了し理由を stderr に出す。その場合は解析を中断し、原因を呼び出し元へ返す（独断で別論文に切り替えない）。

## analysis.md のフォーマット（要点抽出の規約）

`paper_fulltext.txt` を読み、以下の構造で `work/<run-id>/analysis.md` にまとめる。**要点抽出は原文への忠実性を最優先**とし、推測・誇張・原文にない主張を加えない。記事執筆と fact-check の双方がこの `analysis.md` を素材・照合元とするため、原文の主張・数値は出典が辿れる形で残す（`analysis.md` の位置づけと fact-check の二重照合については前節「一次資料と二重照合の約束」を参照）。

```markdown
---
arxiv_id: <2401.12345>
title: <原題（英語のまま）>
authors: [<著者>, ...]
categories: [<カテゴリ>, ...]
abs_url: <https://arxiv.org/abs/...>
pdf_url: <https://arxiv.org/pdf/...>
---

# 書誌情報
- タイトル（原題）/ 著者 / 投稿先・カテゴリ / arXiv ID

# 一言サマリ
この論文が何を達成したかを 1〜2 文で（原文に忠実に）。

# 背景と課題
この研究が取り組む問題・既存手法の限界。

# 提案手法
中核アイデアと仕組み。専門用語は原語を併記する。

# 実験と結果
- データセット / 比較対象 / 主要な評価指標
- **重要な数値・主張（出典付き）**: 記事の事実根拠となる定量結果や主張を箇条書きにし、各項目に原文の根拠（節名・図表番号・ページ等、`paper_fulltext.txt` 上で辿れる手掛かり）を併記する。

# 結論と意義・限界
著者の結論、研究の意義、明示されている限界・今後の課題。

# 専門用語メモ
記事で噛み砕くべき専門用語と、その原文での定義・用法。
```

### 忠実性のルール

- 数値・固有名詞・モデル名・指標は原文の表記と一致させる。曖昧な場合は無理に断定せず、原文の該当箇所が判別できる形で残す。
- 原文にない比較・評価・主張を `analysis.md` に書かない（それは記事執筆段階の脚色であり、fact-check で弾かれる）。
- 図表でしか示されない数値は「Figure 3 より」等の手掛かりを添えて転記する。
