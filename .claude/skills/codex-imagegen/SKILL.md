# codex-imagegen — Codex 組み込み画像生成スキル

## 目的

Codex CLI (`codex exec`) の組み込み `image_gen` ツール（`$imagegen` トリガで起動）を Bash 経由で呼び出し、**gpt-image（image 2.0）** が生成した PNG を指定の絶対パスに保存する。OpenAI API キーは不要で、Codex 自身のサブスクリプション経由で生成される。


## 前提条件

- `codex` CLI が PATH に通っていること（macOS: `brew install codex` 等）。本リポジトリの想定バージョンは `0.130.0` 以降。
- Codex CLI が既にログイン済みであること（`codex login` 済み、または認証ファイル `~/.codex/auth.json` が有効）。
- `~/.codex/skills/.system/imagegen/SKILL.md` が存在すること（Codex の標準同梱スキル。通常自動配置されている）。

## 制約事項（重要）

- **唯一の生成手段は gpt-image（image 2.0）の直接出力**: `$imagegen` 経由で起動される gpt-image の出力 PNG のみ使用する。NEVER スクリプトによる画像描画（Swift / Objective-C / Core Graphics / Python / Pillow / Cairo / HTML+Canvas など）。NEVER SVG 中間ファイル経由（手書き SVG・`rsvg-convert` / `convert` / `magick` などでのラスタライズ含む）。Codex エージェントが日本語多文字レイアウトの困難をスクリプト描画や SVG ラスタライズで迂回する事例があるため、呼び出し側プロンプトでも明示的に禁止する。
- **解像度は近似値で生成され、Codex エージェントが `sips` で後処理リサイズする**: 例えば「1920x1080」を要求すると Codex 側は 1672x941 程度で生成し、後処理で正確な 1920x1080 にリサイズする。後処理込みで最終サイズは保証されるが、初回生成サイズは制御できない点に留意する。
- **保存先絶対パスはプロンプト本文に明示する必要がある**: 組み込み `image_gen` ツール自体には保存先パス引数がない。プロンプト中で「`<absolute-path>` に保存してください」と Codex エージェントへ依頼し、エージェント側で `cp` / `mv` 操作を行わせる。
- **生成 PNG の副産物**: `~/.codex/generated_images/<session-id>/ig_<hash>.png` に Codex 側の元ファイルが残る。ワークスペースにコピー後も削除されない。長期運用ではディスク使用量に注意（必要に応じて手動掃除）。
- **負の指示は弱い**: 「〜しないで」よりも「〜で」「〜を中央に配置して」など肯定形・具体化のほうが画像モデルに伝わる。

## コマンド形

### 基本（参照画像なし）

```bash
codex exec \
  --sandbox workspace-write \
  --skip-git-repo-check \
  '<プロンプト本文>' \
  < /dev/null
```

- プロンプト本文の冒頭で `$imagegen` トリガを必須付与する（半角ドル＋小文字）。
- `--sandbox workspace-write`: ワークスペースへの書き込み権限。必須。
- `--skip-git-repo-check`: CWD が git リポジトリでなくても実行可能にする（呼び出し元のディレクトリ状態に依存しないため常時付与する）。
- `< /dev/null`: 標準入力を閉じて「Reading additional input from stdin...」の不要な待機を回避する。
- プロンプト末尾には **保存先絶対パス** を必ず明示する（例: `/abs/path/to/images/cover.png に保存してください`）。
- 1 回の生成で 30 秒〜2 分程度かかるため、`Bash` ツール側のタイムアウトを長めに（例 `300000` ms）設定する。

### 参照画像つき（スタイル統一・コンポジション参照など）

```bash
codex exec \
  --sandbox workspace-write \
  --skip-git-repo-check \
  -i <reference-image-1.png> \
  -i <reference-image-2.png> \
  '<プロンプト本文>' \
  < /dev/null
```

- `-i` を複数回繰り返すか、カンマ区切り（`-i a.png,b.png`）で複数渡せる。最大 16 枚まで。
- プロンプト本文で各参照画像の **役割** を明示する（例: `Image 1: style reference`、`Image 2: composition reference`）。

## プロンプト設計の作法

呼び出し側（`article-image-generator` など）は次のテンプレートに従ってプロンプト本文を組み立てる。

```text
$imagegen 次の仕様で画像を生成してください。

スタイル: <呼び出し側が指定するスタイル宣言>
アスペクト比: <呼び出し側が指定するアスペクト比（本文中に明記。コマンドラインフラグでは指定不可）>
解像度: <呼び出し側が指定する解像度（本文中に明記。後処理で sips リサイズされる）>
画像内テキスト: <呼び出し側が指定する言語>

題材: <呼び出し側が渡す画像プレースホルダ仕様の説明文から導いた主題を 1〜2 文で>
構図: <主要要素の配置を肯定形で具体的に。例「中央上部に黒文字で『xxx』を大きく配置、周囲にノートPC・ペン・雲のシンプルアイコンを小さく配置」>
配色: <呼び出し側が指定したスタイルに沿う配色を 2〜4 色列挙>

画像内に表示するテキスト（verbatim）: "<記事内に表示する確定文言>"

最終保存先（絶対パス）: <article-dir>/images/<name>.png に保存してください。
```

ポイント:

1. **冒頭で `$imagegen` トリガを必須付与**（これがないと `imagegen` スキルがロードされず通常の Codex 応答になる）。
2. **呼び出し側が指定したスタイル仕様を肯定形で宣言する**（呼び出し側テンプレートの各項目をそのまま並べる）。否定形は使わない。
3. **呼び出し側が指定したアスペクト比・解像度を本文中に書く**（コマンドラインフラグでは指定できないため。例: 「アスペクト比 16:9 のランドスケープ」「解像度 1920x1080」のように本文へ明記する）。
4. **画像内に出すテキストはダブルクォートで囲み verbatim 指定**。半角英数の語はそのまま記載し（例: `"Claude Code"`）、日本語・漢字を含む語は表示する確定文言をそのまま明記する（例: `"クロードコード"`）。
5. **要素・配置・色を肯定形で「足す」方向に書く**: reviewer から FAIL の `revision-hint` を受け取った場合も、`prompt-engineering` の到達点を書く原則に従い、追加すべき要素・調整方向として書く。
6. **保存先絶対パスをプロンプト末尾で明示**: Codex エージェントが受け取ったら `cp` / `mv` で配置する。
7. **生成手段を gpt-image 直接出力に限定する旨を明記**: 「`$imagegen` 経由の gpt-image（image 2.0）出力のみ使用。SVG 中間ファイル・Swift / Objective-C / Python などのスクリプト描画は禁止」とプロンプト本文に書く（詳細は「制約事項」参照）。Codex エージェントは日本語レイアウトが難しいと感じるとスクリプト描画に迂回する傾向があるため、肯定（「gpt-image 出力のみ」）と禁止（「SVG・スクリプト描画なし」）の両面で明示する。
8. **参照画像を渡す場合は本文中で各 `Image N` の役割を明示する**: `codex exec -i` で渡したファイルは Codex 側に `Image 1, Image 2, ...` の順で並ぶ。プロンプト本文の `### 参照画像の役割` セクションで「何のための参照か」「画像内のどこに配置するか」「色・形状をどう踏襲するか」を肯定形で書く。テンプレートは下記「参照画像つきの場合のテンプレート追補」を参照。

### 参照画像つきの場合のテンプレート追補

`codex exec -i <path>` で 1 枚以上の参照画像を渡す場合、上記テンプレートに `### 参照画像の役割` セクションを差し込んで使う。`-i` で渡した順序が Codex 側の `Image 1`, `Image 2`, ... の連番と一致する。

```text
$imagegen 次の仕様で画像を生成してください。

スタイル: <呼び出し側が指定するスタイル宣言>
アスペクト比: <呼び出し側が指定するアスペクト比（本文中に明記。コマンドラインフラグでは指定不可）>
解像度: <呼び出し側が指定する解像度（本文中に明記。後処理で sips リサイズされる）>
画像内テキスト: <呼び出し側が指定する言語>

### 参照画像の役割
Image 1: <1 枚目の役割。例: Anthropic Claude Code 公式アイコン。色味とシンボル形状を踏襲し、画像中央左に大きく配置する>
Image 2: <2 枚目の役割。例: OpenAI Codex 公式アイコン。Image 1 と並列対比させるため画像中央右に同サイズで配置する>

題材: <呼び出し側が渡す画像プレースホルダ仕様の説明文から導いた主題を 1〜2 文で>
構図: <主要要素の配置を肯定形で具体的に。各 Image を画像内のどこに配置するかも明示する>
配色: <呼び出し側が指定したスタイルに沿う配色を 2〜4 色列挙。Image のブランド色との調和も意識する>

画像内に表示するテキスト（verbatim）: "<記事内に表示する確定文言>"

最終保存先（絶対パス）: <article-dir>/images/<name>.png に保存してください。
```

ポイント:

- **`### 参照画像の役割` セクションは宣言ブロックの直後に置く**（スタイル統一仕様の宣言の後、題材の前）。位置を固定することで Codex 側が役割宣言を確実に拾う。
- **`Image N` の番号は `-i` で渡した順序と完全一致させる**。順序が崩れると役割の取り違えが起きる。
- **役割は「何の参照か」だけでなく「画像内のどこにどう配置するか」「色 / シンボル形状をどう活かすか」まで肯定形で書く**。単なる「Image 1: 参照画像」では Codex 側の解釈が拡散する。
- **参照画像が 0 枚の場合は本セクション自体を入れない**（空セクションを置かない）。

## 戻り値の確認

`codex exec` の実行後、呼び出し側は次の手順で結果を検証する:

1. `codex exec` の終了ステータスが `0` であること。
2. 期待する絶対パスに PNG ファイルが実在し、サイズが妥当（数十 KB 以上）であること。`Read` ツールで視覚的に開いて確認するのが確実。
3. 標準出力末尾に Codex エージェントの最終メッセージ（保存パスの明示、QA ノート）が出るので参考にする。

ファイルが期待パスに存在しない場合は失敗扱い。プロンプト中の保存先指示が曖昧だった可能性が高いため、保存パス指示を強化（パスを明確に絶対パスでバッククォート囲み、「に確実に保存してください」と再強調）して再実行する。
